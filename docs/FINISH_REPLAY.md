# 结束投入的回执与接口约定

## 请求重放

`Service::execute` 继续负责请求大小、请求标识、重放、版本检查和命令分发。结束投入、保存最后进展、可选完成待办及周期规则变化由 `crates/catch-app/src/finish.rs` 组合提交。

结束成功后，回执永久保留请求 ID 和请求 JSON 的 SHA-256 摘要。同一 ID 携带不同参数时返回 `CONFLICT`。身份记录随成功结束次数线性增长，用于跨重启防止重复执行。

完整响应按照提交顺序优先保留最近的记录，同时受 32 份和 8 MiB 正文总量限制。超出额度的响应正文会被压缩清除，身份记录继续保留。单份正文超过 8 MiB 时直接保留身份记录。8 MiB 限制响应正文的 UTF-8 字节数，回执文件还包含 JSON 转义和身份记录。

仍保留正文的请求，在当前进程和重启后均返回原来的响应。正文已经清除的旧请求返回 `CONFLICT`，提示“该结束操作已处理，历史响应已压缩，请刷新状态”。客户端应刷新权威状态，避免把旧请求当作新操作再次发送。

上述原响应约定属于 `Service::execute`。桌面传输层通过共享的 `Reply` 类型向界面返回当前权威快照，避免历史快照中的旧版本号影响界面后续操作。命令成功或失败、错误码以及当前成长信息按同一个回复结构传输。

回执索引在服务启动时载入，并在结束事务整体成功后更新。结束回执使用独立索引，普通请求缓存不再保存结束响应。新的结束提交仍检查磁盘前像，发现回执主文件被外部修改或删除后会停止写入。

## 磁盘格式和迁移

`catch-finish-receipts.json` 升级为带 `version: 2` 的文档。请求摘要保存为十六进制字符串，响应正文保存为 JSON 文本字符串。

启动时先恢复未完成事务，再读取回执。旧版数组回执会先按原始字节备份到 `catch-finish-receipts.json.bak`，再原子替换为新格式并执行正文额度策略。后续结束操作继续轮换该备份，因此它表示最近一次覆盖前的内容。

新版数据需要使用本版或后续兼容版本。回滚程序时，需要同时考虑回执格式及整个数据目录的时间点，避免单独把旧回执备份覆盖到已经继续变化的活动和待办数据上。

`catch-finish-pending.json` 的新版日志使用 `version: 2`，文件前像和后像直接保存 UTF-8 JSON 文本，降低逐字节数字数组的编码开销。恢复器同时支持旧版 `version: 1` 的字节数组日志。事务仍覆盖活动、待办、周期规则和回执四个文件，失败后先恢复，状态无法确认时阻止后续写入。

## 前后端契约验证

`crates/catch-app/tests/ipc_contract.rs` 通过真实 Rust 类型和 Serde 序列化生成 `frontend/test/fixtures/rust-ipc.json`。常规 Rust 测试比较样例与当前序列化结果，字段变化需要显式更新样例。

`frontend/test/ipc-contract.test.ts` 将样例作为只读字面量交给 TypeScript 编译器，检查实际使用的 `Reply`、其中的 `Snapshot` 和 `GrowthView`、结束请求、请求信封及错误枚举。样例覆盖成功和失败回复、不同事项状态、资料种类、回收站、周期规则、植物类型、空值和默认字段。反例检查把事项 ID 改成数字，确认校验能发现不一致。

桌面请求构造使用 `IpcRequest`，结束投入入口使用 `FinishRequest`。新增接口或枚举分支时，应扩展样例覆盖范围。

需要更新契约样例时，在仓库根目录执行以下命令，然后审阅样例变化并运行前端验证。

```powershell
$env:UPDATE_IPC_CONTRACT = '1'
.\tools\rust.ps1 -Action test
Remove-Item Env:UPDATE_IPC_CONTRACT
node frontend/node_modules/prettier/bin/prettier.cjs --write frontend/test/fixtures/rust-ipc.json
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run check
```

## 回归检查

- 保留原有结束事务所有 I/O 边界的错误和中断恢复测试。
- 验证旧回执迁移备份、迁移中写失败、旧恢复日志、外部回执修改和正文总量限制。
- 连续结束 40 次，验证近期原响应重放、旧响应清除后拒绝重复执行、跨重启行为和参数冲突。
- 连续执行 50 个普通命令并重放结束请求，验证回执文件读取次数为零。

迁移及故障测试使用临时目录或内存磁盘。正式数据目录的迁移在用户启动新版程序时发生。
