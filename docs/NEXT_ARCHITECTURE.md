# 下一版架构（迁移中）

当前稳定版本仍是 Electron。Rust 后端已接入 `frontend/` 下的 Vue/TypeScript 界面，`src-tauri/` 提供 Windows 本地预览入口；新版尚未完成整体验收。

## 依赖方向

Vue/TypeScript 界面 → Tauri 命令边界 → 应用服务 → catch-core。
持久化和 Windows 桌面适配器由应用服务调用；业务核心不依赖它们。

- `crates/catch-core`：事项、投入、时间段、待办、周期规则和每日成长的类型、验证与状态变更。时间和 ID 由调用方传入，可在没有窗口时运行。
- `crates/catch-storage`：JSON 兼容、迁移前备份、原子写入、故障恢复和数据目录锁。只有保存成功的候选状态才能提交给界面。源码中的 Electron 入口已参与同一文件锁，并通过进程级双向互斥测试；已经运行的旧二进制不会自动获得此保护，因此新版仍使用独立目录。
- `crates/catch-app`：请求验证、版本冲突、请求重放和跨模块操作。使用待办开始事项时读取权威待办内容；界面不能调用系统检查点或提交系统暂停时间。
- `src-tauri/`：系统通知、资料选择/打开和窗口交接。Windows 植物使用独立 Win32 分层窗口，不依赖 Tauri 的不稳定 WindowBuilder API。
- `frontend/`：Vue 界面负责展示和编辑草稿；不决定计时、周期生成或每日植物锁定规则。收起前保存草稿及页面位置，收到确认才释放 WebView；失败则保留界面。

Rust 应用服务持有唯一权威状态并串行执行命令。每次变更带预期版本；冲突返回当前状态，保留用户草稿。渲染器创建或销毁不开始或停止计时。真实锁屏、睡眠与退出通知交给核心处理。

## 兼容与迁移

迁移先对照原版产生的合成操作轨迹，比较完整记录与拒绝结果，再替换运行时。旧版事项 ID、投入 ID、资料快照和回收站条目必须保留。未知数据版本拒绝写入；不把解析失败的数据当作空文件。

旧版 Electron 在验收前保留。正式新版与旧版的数据写入互斥及迁移备份通过后，才允许访问用户数据。所有可行性测试使用 `artifacts/` 下的合成数据。

当前验证命令为 `./tools/rust.ps1 -Action test` 和 `./tools/rust.ps1 -Action clippy`。行为对照样本来自原版 JavaScript 业务代码，存放于 `crates/catch-core/tests/fixtures`；测试不自行重生成预期结果。修改规则时，运行 `tools/tracking-parity.cjs` / `tools/todos-parity.cjs` 后必须审阅差异。

## 新功能的状态归属

- 每日植物和目标：`catch-growth.json`，由 Rust 保存后才确认选择。日期由可信宿主时区决定，不接受界面传入“今天”。历史选择不能被新日期或改目标覆盖；预览不写此文件。达成反馈先保存每日一次的记录，再通知界面。
- 资料：待办和事项各自持有 `resources` 快照；从待办开始时复制。删除待办不会让事项资料失效。打开操作由桌面适配器根据已保存的关联 ID 查找目标；移除关联仅修改 JSON。
- 周期：模板和游标在 `catch-recurrences.json`，实例保留在兼容的 `todos.json` 数组中。`catch-schedule-pending.json` 为两文件提供恢复事务；不会只保存新实例而遗漏游标。一个模板最多有一项未完成实例，漏过多期只生成最近一期；完成后推进到下一个未来计划日。月末日期不足时取当月最后一天。

Tauri 组合入口使用单一互斥锁保护应用服务，并在启动和跨日调用周期检查。Vue 界面初稿已经接入，仍需完成真实窗口交互、安装包和演示网站联调。界面方向的确认与整体验收、发布授权分别记录。

## 已验证的资源边界

普通双 WebView Tauri 未明显降低内存；原生悬浮表面加按需主 WebView 的原型在这台机器上有收益。悬浮短测约 8.25 MB 私有工作集，展开约 99.91 MB；原型 NSIS 为 1.73 MiB。数字属于功能不完整的原型，成品需重新测量。内部原始证据保存在本地 `artifacts/catch-next/`。
