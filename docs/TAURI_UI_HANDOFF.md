### 本轮尺寸与留白修正根因

- `report_layout` 原先每次页面 resize 都重新 `set_min_size`；Tao 的该 API 内部又调用 `set_inner_size`，与拖动形成尺寸反馈。现在按 HWND＋generation＋物理内容下限缓存，只在新窗口或 DPI/文字缩放变化时校准一次。失败清缓存允许重试，不持有 Runtime 锁调用窗口尺寸 API。
- 真实边缘拖动发现去除循环后仍能缩到 250 CSS 像素。检查 Tao Windows 源码确认：无装饰换算省略隐藏边框，而本程序透明 HWND 仍有非客户区。现以实际 outer−inner 差值补偿跟踪约束及一次性初始纠正，不用每次 resize 强拉回去。DPI=2/DPR≈2.56 实测外框差 26×15 物理像素，最小内容 666 物理像素对应 261 CSS 像素。
- 待办新增框在 `base.css` 的 `max-width:285px` 遗留规则加了 9px padding，造成窄窗上下空白增加；已删除该 padding。320/286/285/280/260 实测新增框高度均约 41.6 CSS 像素。
- 共享投入条目与未计时统一为 30px 时间列、3px 色条、5px 间隔，并收紧列表左侧边距；避免只调整一种条目造成错位。

### Rust 命令与安全恢复

实现位于 `crates/catch-core/src/tracking/timeline.rs`，通过既有 tracking 命令入口调用：

```text
merge-sessions { first:{activityId,sessionId}, second?:{activityId,sessionId}, gap?:{startTime,endTime}, targetActivityId }
split-session { activityId, sessionId, atTime }
begin-session-edit { activityId, sessionId, progress? }
finish-session-edit { activityId, sessionId, editToken, cancel, startTime?, endTime?, progress?, segments? }
```

`second` 与 `gap` 二选一。`begin-session-edit` 返回的 `pauseReason` 为 `edit:<token>`；结束编辑用该 token 和持久化 session 快照校验中途变化。若编辑期间另一个事项已开始，不抢走它的运行状态。保存先执行既有 EditSession 校验，再同一提交恢复本次投入。进程中断后仍遵循现有中断恢复规则，不默默继续计时。

## 后续“正在做”设计时需要了解的业务

- 同时只有一个事项运行，可以有多个后台暂停事项。
- 前台卡片会保留手动暂停的事项，继续时沿用同一事项及累计投入。
- 计时以 Rust 的有效投入区间和 sessions 为准，切换 WebView 或收起窗口后仍由宿主管理。
- 待办完成和计时结束保持独立；用户明确选择“结束并完成待办”时，通过本轮新增的可靠组合事务联动。
- 本次进展保存、下一步、暂停、结束、结束摘要和详情入口均有现有调用方，修改时需要检查对应正常入口。
