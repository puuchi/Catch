# 以主进程单一写入和模块化业务核心组织 Catch

Catch 的可靠性依赖计时、待办、双窗口和本地文件的一致协作。目标采用 Electron 内的模块化单体：领域规则不依赖 Electron、DOM 或文件系统，应用服务组织操作，主进程统一接收并串行处理写命令，界面只持有展示快照和编辑草稿；依赖由一个启动入口装配。

首轮保留现有 JavaScript 及活动 JSON 格式，通过 JSDoc/checkJs 和运行时校验明确接口，避免在来源重写时同时更换语言、框架和数据格式。JSON 的跨文件保存缺陷由范围有限、可恢复的归档流程解决，不建立通用事务框架；如果真实数据规模或新增的跨模块事务使这个方案失去优势，再单独评估 SQLite 迁移。此选择减少现有功能和数据迁移风险，代价是必须验证归档中断恢复、串行写入和存储错误，不能把单文件原子替换当作多文件事务。

保留本人及已授权贡献，允许通过适配器逐步拆开现有模块，但适配器仅作迁移过渡。详细边界、故障语义和验收要求见 [目标架构](../CATCH_ARCHITECTURE.md)。2026-11-13 已在 2.0.0 实施，并由类型检查、依赖检查、业务/存储测试和 Electron 回归验证。具体覆盖与限制见验证记录。
